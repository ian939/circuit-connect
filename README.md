# 충전기 정비사 (Circuit Connect)

전기차 충전 앱용 **리텐션 미니게임** 프로토타입입니다.
플레이어는 **고장 신고를 받고 출동하는 충전기 정비사**가 되어, 끊어진 배선을 다시 이어
충전기를 되살립니다. 수리할 때마다 충전 포인트가 적립되고, 매달 시즌 랭킹으로 경쟁합니다.
의존성 없는 **단일 HTML 파일**(+ 스토리 이미지 2장)로 동작합니다.

## 플레이

두 가지 버전이 나란히 배포돼 있습니다. 기능은 완전히 동일하고 **외형만 다릅니다.**

| 버전 | 링크 | 설명 |
| --- | --- | --- |
| 오리지널 | **https://ian939.github.io/circuit-connect/** | 다크 네온 테마 (`index.html`) |
| SK일렉링크 DS | **https://ian939.github.io/circuit-connect/skel.html** | 디자인 시스템 1.0 적용 (`skel.html`) |

## SK일렉링크 디자인 시스템 1.0 적용 (`skel.html`)

[디자인 시스템 문서](https://appweb.electlinkdev.com/design-system/for-ai)의 `llms.txt` 규칙을 그대로 적용한 버전입니다.
로직·JS는 오리지널과 **한 줄도 다르지 않고**, 토큰과 스타일만 교체했습니다.

| 항목 | 적용 |
| --- | --- |
| 색 | 라이트 테마. `brand.solid #7b42ff` / `bg.base #f3f4f6` / `bg.elevated #fff` / text 3단계 / status 3종 |
| 서체 | Pretendard 단일. 타입 스케일 **6단계(28·22·18·16·14·12)만** 사용 |
| 간격 | 전부 4px 배수. 화면 좌우 패딩 16px |
| 라운드 | `--r-sm/md/lg/xl/full` 5단계만 |
| 그림자 | `--e1/e2/e3` 3단계만. 그림자와 보더를 동시에 쓰지 않음 |
| 컴포넌트 | SkelButton(h56·r16·화면당 primary 1개) / SkelCard(r20·p20) / SkelBadge(pill·tone) / SkelSection 규칙 준수 |

숫자는 별도 모노 서체 대신 Pretendard의 `tabular-nums`로 정렬해 "서체는 Pretendard 하나" 원칙을 지켰습니다.

> ⚠️ **한 곳은 의도적으로 팔레트 밖 색을 씁니다 — 게임 보드의 배선 8색.**
> 색 맞추기 퍼즐이라 서로 구분되는 8색이 게임 규칙 자체이고, 브랜드 퍼플과 그레이만으로는 성립하지 않습니다.
> UI 크롬은 100% 토큰을 따르고, 배선은 **UI 토큰이 아닌 게임 데이터**로 취급했습니다.
> 그마저도 1번 색을 `brand.solid`로, 2~4번을 `status` 3색으로 두고 나머지만 색상환을 벌려 밝은 표면에 맞게 재조정했습니다.
> `--w1 ~ --w8` 변수 한 곳에 모아뒀습니다.

또는 `index.html` / `skel.html`을 브라우저에서 그냥 열면 됩니다.

## 스토리

첫 진입 시 3컷 인트로가 재생됩니다.

| # | 장면 | 내용 |
| --- | --- | --- |
| 1 | 고장 접수 | "충전소가 고장 났어요" — 신고가 정비반으로 접수 |

이미지는 원본 PNG(6MB)를 960px WebP(~70KB)로 리사이즈해 `story-1.webp`, `story-2.webp`로 넣었습니다.

## 모드

### 1. 정비 교육 (1~5과정)

첫 진입 시 **가이드가 자동으로 뜹니다** (드래그 시연 + 3단계 규칙). 이후엔 헤더의 `?` 버튼으로 언제든 다시 볼 수 있습니다.

5×5 / 4색에서 시작해 7×7 / 6색까지 완만하게 올라갑니다.
**5단계를 통과하면 온보딩은 완전히 사라집니다.** 이후 접속하면 탭 없이 곧바로 랭킹전 홈이 열립니다.

장치를 하나씩만 추가해 익히게 합니다.

| 과정 | 1 | 2 | 3 | 4 | 5 |
| --- | --- | --- | --- | --- | --- |
| 보드 | 5×5·4색 | 5×5·4색 | 6×6·5색 | 6×6·5색 | 7×7·6색 |
| 배선 상한 | – | – | ✓ | ✓ | ✓ |
| 탄 자리 | – | – | – | 3 | 4 |

### 2. 오늘의 출동 (매일 3건)

| # | 정비 대상 | 보드 | 탄 자리 | 배선 여유 | 채울 칸 |
| --- | --- | --- | --- | --- | --- |
| 1 | 100kW 충전기 | 6×6 · 5색 | 3 | +4 | 33 |
| 2 | 200kW 충전기 | 7×7 · 6색 | 5 | +3 | 44 |
| 3 | 350kW 충전기 | 8×8 · 7색 | 8 | +2 | 56 |

#### 난이도 장치 2가지

- **배선 길이 상한** — 단자에 숫자가 뜹니다. `더 늘릴 수 있는 칸수`이고, 0이 되면 그 배선은 더 못 늘어납니다(보드가 살짝 흔들려 알림).
- **탄 자리** — 빗금 친 칸. 지나갈 수 없습니다. 채움률 계산에서도 빠집니다.

두 장치는 판을 키우지 않고 난이도만 올립니다. 10×10(100칸)에서 8×8(56칸)으로 **칸 수는 거의 절반**인데 체감 난이도는 더 높습니다.

#### 왜 이 숫자인가 — 해 개수로 측정

정답의 개수를 세서 난이도를 정량화했습니다. 정답이 많을수록 아무렇게나 그어도 맞는다 = 쉽다는 뜻입니다.

| 조건 (8×8) | 정답 개수 중앙값 |
| --- | --- |
| 제약 없음 (기존) | **524개** |
| 탄 자리만 | 12개 |
| 상한만 (여유 +0) | 2개 |

- 보드가 클수록 오히려 **느슨해집니다** — 6×6 28개 → 7×7 78개 → 8×8 524개 → 9×9 이상은 400만 노드로도 못 셀 정도. 10×10은 난이도가 아니라 소요 시간만 늘리던 것.
- 배선 여유는 **+2 이상에서 포화**됩니다(+2와 +3의 결과가 같음). 여유값이 실질적인 난이도 다이얼입니다.

#### 생성 시 난이도 검증

여유값만으로는 정답 개수가 들쭉날쭉해서(6×6은 20판 중 6판이 3개 미만), 생성 후 **해를 세어 3~24개 범위가 아니면 시드를 바꿔 다시 뽑습니다.** 재추첨 중앙값 1~2회, 생성 시간 최악 64ms로 체감되지 않습니다.

배선 최소 길이는 4칸입니다(2칸짜리 공짜 배선 방지).

- **판이 열리는 순간부터 시간이 카운트**되고, 완주 시간이 그날의 기록이 됩니다.
- 랭킹은 **최단 시간 순**.
- **완주하면 곧바로 랭킹 화면으로 이동**합니다. 내 시간·순위·적립액을 상단 배너에 보여주고,
  `챌린지 홈으로`를 누르면 3판 목록으로 돌아갑니다. 보드 화면에 머무르지 않습니다.
- 완주한 판은 **종료**됩니다. 카드를 다시 누르면 게임이 아니라 랭킹이 열립니다.
- 매일 자정에 새 문제 3개로 초기화됩니다.

## 어뷰징 차단 설계

현금성 포인트가 걸려 있어 다음 경로를 막았습니다.

| 경로 | 차단 방식 |
| --- | --- |
| 온보딩 '처음부터'로 무한 파밍 | `paidStage`에 지급 완료 단계를 기록, 재클리어 시 무지급 |
| 챌린지 '다시 시작'으로 타이머 리셋 | 챌린지 모드에서는 **'새 판' 버튼 자체를 제거** |
| 나갔다 재입장해 타이머 리셋 | 최초 입장 시각(`start`)을 저장, 재입장 시 **이어서 카운트** |
| 완주 후 재도전으로 기록 세탁 | 완주 시 판을 잠그고 카드 탭 → 랭킹으로 연결 |
| 판을 여러 번 열어 문제 고르기 | 문제는 날짜 시드로 고정 — 몇 번을 열어도 같은 문제 |

> ⚠️ **위 방어는 UX 레벨입니다.** `localStorage`는 사용자가 조작할 수 있으므로
> 실제 지급은 반드시 서버에서 재검증해야 합니다 (하루 3판 상한, 판별 1회 지급, 완주 여부).

중도 이탈해도 그려둔 선은 저장되어 이어서 풀 수 있습니다 (시간은 계속 흐름).

## 랭킹

랭킹은 두 종류입니다. 완주 후 열리는 시트에서 탭으로 전환합니다.

### 오늘 기록
충전기별 그날 수리 시간 순위. 가장 빨리 고친 순서.

### 시즌 랭킹 (매달)
그날 순위에 따라 시즌 점수가 누적됩니다. **하루 최대 15점.**

| 그날 순위 | 획득 점수 |
| --- | --- |
| 1위 | 5점 |
| 2위 | 4점 |
| 3위 | 3점 |
| 4~10위 | 2점 |
| 11위 이하 | 1점 |

시즌은 매달 1일 시작 / 말일 종료. 종료 시 최종 누적 점수 순위로 보상을 지급하고,
다음 시즌 첫 접속 때 자동 적립 + 안내 배너가 뜹니다.

> ⚡ **보상 자격: 누적 100점 이상.** 100점 미만이면 순위와 무관하게 보상이 없습니다.
> 하루 최대 15점이므로 3건을 꾸준히 수리하면 약 10일이면 도달합니다.

| 최종 순위 | 보상 |
| --- | --- |
| 🥇 1위 | 5,000P |
| 🥈 2위 | 3,000P |
| 🥉 3위 | 2,000P |
| 4~10위 | 1,000P |
| 11~100위 | 500P |

시즌 랭킹 안에 **ⓘ 랭킹 안내** 버튼이 있어, 위 규칙 전체를 앱 안에서 볼 수 있습니다.
1P = 1원입니다.

> 📌 **원문 스펙에서 두 곳을 보완했습니다.**
> · 일일 점수의 "3~10위 2점"은 3위(3점)와 겹쳐 **4~10위 2점**으로 처리했습니다.
> · 시즌 보상의 "5-10위 1000P"는 4등이 비어 있어 **4~10위 1000P**로 처리했습니다.
> 의도가 다르면 `SEASON_PTS` / `SEASON_PRIZE` 한 줄씩만 고치면 됩니다.

## 특징

- 레벨 생성기가 해밀턴 경로(zig-zag + backbite 셔플)를 잘라 색을 배정하므로 **항상 정답이 존재하는 판**만 나옵니다.
- 챌린지는 `날짜 + 챌린지 번호`를 시드로 쓰는 결정적 난수(mulberry32)로 생성됩니다.
  → **같은 날이면 누구에게나 똑같은 문제**가 나오므로 기록 비교가 공정합니다.
- 진행도·기록은 `localStorage`에 저장됩니다 (`circuit-connect.v2`).
- 마우스·터치 모두 지원. 태블릿 롱프레스 시 뜨는 복사/잘라내기 콜아웃 차단.
- `prefers-reduced-motion` 대응.
